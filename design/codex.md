# Codex

Moved from CLAUDE.md. Codex is the `Harness.codex` descriptor in BerthCore `Harness.swift` (docs/adr/0007): capabilities `.conversation`, `.contextSize`, `.pullRequestLinks`, `.needsYou`, `.idleUnload`, `.worktrees` and `.remote`, `liveSource` `.tabSignals` with `CodexLive.sessions` as `readLive`, `isOptIn` (listed only while enabled, marked on rows by its glyph and name), a `claim` that adopts a new tab's rollout and `CodexTranscript.read` as its transcript adapter. The UI asks `agent.harness.supports(_:)`, `liveSource` or `isOptIn`, never `agent == .codex`; a third agent is a new descriptor.

Codex (Settings > General `codexEnabled`, off by default): BerthCore `CodexRollout` + `CodexIndex` read `$CODEX_HOME/sessions/**/rollout-*.jsonl` and `session_index.jsonl` into `SessionSummary` with `agent: .codex` (interactive rollouts only: `thread_source` user, originator not `codex_exec` or `Claude Code`; title is the newest index name, else the first `user_message`; context is the last `last_token_usage.input_tokens` over `model_context_window`, unknown after `compacted`). `CodexLaunch` runs `codex resume "$BERTH_SESSION_ID"`; ⌥⇧↩ in ⌘N starts `codex` through `Store.openSession(.codex, …)` and the tab claims the first new rollout by cwd and start time (`Harness.claim`, applied by `Store.claimNewSessions`). A tab in a new worktree has a different cwd than its rollout, so the claim falls back to the earliest rollout in a linked worktree of the tab's repository when no cwd matches exactly.

Model and effort: `CodexModels` reads `models_cache.json` in the Codex directory (visibility `list`, by priority) for display names and supported efforts. Settings > General > Agents stores the choice under `launchModel.codex` and `launchEffort.codex`; `Store.openSession` passes it as `LaunchOptions` and `CodexLaunch` adds `-m` and `-c model_reasoning_effort=` (values validated, never written to `config.toml`). It applies to every start and resume Berth makes. A running session's model cannot be changed from Berth: driving the TUI's `/model` picker is unverified, so `.modelEffortMenu` stays off (it also gates attachments). The chip shows the model and effort from the rollout's latest `turn_context`.

Worktrees: `.worktrees` makes `Store.openSession` choose `.newInWorktree`; Codex has no session id flag, so `CodexLaunch` runs `wt switch --create codex-<time> --no-cd -x codex -- …`, the same Worktrunk layout (`<repo>.worktrees/<branch>`) Claude's hook produces. Needs `wt` on the login shell's PATH; otherwise the tab falls back to a shell. Codex's own `--worktree` is not used (it lays worktrees out elsewhere).

Codex tabs have no live file (never locked); Codex sessions appear in the remote (design/remote.md); stored pins, flags, archive, seen and snoozes keep Codex ids (`codexSessionIDs`) while the toggle is off. `-codexEnabled YES` lists rollouts from `CFFIXED_USER_HOME/.codex`; `-snapshotLauncherKeys` knows `alt-shift-enter`.

## Conversation view

The Conversation view reads the rollout through `Harness.readTranscript` and resolves its URL and watch root through `Store.sessionIndex(for:)`. `TranscriptIndex` and `CodexIndex` implement `SessionIndex` (`root`, `url(ofSession:)`). Context is a computed read from the session summary so refreshed token counts and the rollout's context window reach the chip without Claude's activity report. Background tasks are not implemented for Codex.

`CodexTranscript` reads prompts and replies from `event_msg` user_message and agent_message records, including commentary and final replies. It also reads item_completed UserMessage and AgentMessage records. If the head contains item_completed, command execution and file changes use completed items; otherwise commands use response_item function calls and outputs, with patch_apply_end for changes. This era rule prevents duplicate tools. Adjacent duplicate prompts and repeated replies within a prompt are deduplicated. Web searches use web_search_end, and update_plan becomes a plan tool row. Polling and agent bookkeeping calls are omitted. Pull request tags come from standalone GitHub pull URL lines in gh command output.

`task_started` opens a turn; `task_complete` and `turn_aborted` close it. An incremental chunk's nil `isTurnOpen` leaves the previous state intact. A full read reporting an open turn whose newest entry predates the tab is treated as a dead turn. Open turns show Working. After 20 seconds without new entries or a turn-state change, a quiet hint offers Show Terminal. Codex does not use the missing-live-session terminal fallback.

Sending is refused while a turn is open and the draft is kept. Approvals are invisible in the rollout, so Enter could answer one instead of sending a message. Otherwise a tab must already be open, input waits until it is at least five seconds old, and the terminal receives bracketed paste followed by Enter after 300 ms. This sequence is unverified against a live Codex TUI. Stop sends Escape without requiring live status.

Attachments are off for Codex. Its context chip is read-only and opens the shared usage popover. The composer uses the harness name and keeps drops as a no-op when attachments are unavailable.

## Live status

`Harness.readLive` returns `LiveSession` records, so the sidebar dots, Needs Attention, notifications, Dock badge, Triage and idle unload read Codex exactly like Claude. `CodexLive` derives one record per open Codex tab with a session id (pid 0, kind `tab`; `Store.liveBySession` merges every enabled harness and skips pid 0 for orphan, lock and claim logic). `Store` polls every 2 seconds while such a tab is open, because a title change touches no file.

Signals, in order. The TUI terminal title: `CodexLaunch` passes `-c 'tui.terminal_title=["run-state"]'` (per launch, nothing written to `~/.codex`), so Ghostty's OSC title is the run-state label; `CodexRunState` maps Thinking and Working to busy, Needs input and Blocked to waiting, Ready to idle, and anything else to no signal. Without a signal the rollout tail decides: busy when the newest turn is open (`task_started` without `task_complete` or `turn_aborted`, or no turn event in the 256 KiB window) and the file changed in the last 300 seconds, else idle. `statusUpdatedAt` is the rollout's modification time, stable while nothing is written. `LiveSession.observesWaiting` is true only when the title signal was seen. A fresh Codex tab hides the status title (`Harness.isStatusTitle`) and shows New Codex Session until its rollout is claimed.

Waiting reads "needs input" and never matches Claude's permission prompt, so the Conversation view takes its existing unrepresentable path and switches to the terminal; `.approvals` is not claimed, because the TUI's approval keys are configurable and unverified. Sending is refused while waiting, and while busy when the title signal is silent (Enter could answer an approval). With the signal present, a busy tab accepts a queued message like Claude (`ConversationModel.blocksSending`).

Channels not used. `notify` only reports `agent-turn-complete`, which `task_complete` already gives. `approval-requested` is a TUI notification (OSC or BEL on the pty), and the terminal package exposes no notification or bell callback. Hooks need trust entries in `config.toml`, which Berth does not write. The app-server protocol (`thread/status/changed` with `waitingOnApproval`) is the complete source but needs Berth to host the server (`codex --remote`), a larger change. Background tasks are not implemented (`.backgroundTasks` switches the context chip to Claude's activity report).

Unverified against a live TUI: the exact run-state labels, whether `Needs input` covers command and patch approvals, and that the override is accepted by every Codex version (an unknown title item only warns).
