# Codex

Moved from CLAUDE.md. Codex is the `Harness.codex` descriptor in BerthCore `Harness.swift` (docs/adr/0007): capabilities `.conversation`, `.contextSize` and `.pullRequestLinks`, `liveSource` `.notTracked`, `isOptIn` (listed only while enabled, marked on rows by its glyph and name), a `claim` that adopts a new tab's rollout and `CodexTranscript.read` as its transcript adapter. The UI asks `agent.harness.supports(_:)`, `liveSource` or `isOptIn`, never `agent == .codex`; a third agent is a new descriptor.

Codex (Settings > General `codexEnabled`, off by default): BerthCore `CodexRollout` + `CodexIndex` read `$CODEX_HOME/sessions/**/rollout-*.jsonl` and `session_index.jsonl` into `SessionSummary` with `agent: .codex` (interactive rollouts only: `thread_source` user, originator not `codex_exec` or `Claude Code`; title is the newest index name, else the first `user_message`; context is the last `last_token_usage.input_tokens` over `model_context_window`, unknown after `compacted`). `CodexLaunch` runs `codex resume "$BERTH_SESSION_ID"`; ⌥⇧↩ in ⌘N starts `codex` through `Store.openSession(.codex, …)` and the tab claims the first new rollout by cwd and start time (`Harness.claim`, applied by `Store.claimNewSessions`).

Codex tabs have no live file (never locked, unloaded or needs-you) and are excluded from the remote; stored pins, flags, archive, seen and snoozes keep Codex ids (`codexSessionIDs`) while the toggle is off. `-codexEnabled YES` lists rollouts from `CFFIXED_USER_HOME/.codex`; `-snapshotLauncherKeys` knows `alt-shift-enter`.

## Conversation view

The Conversation view reads the rollout through `Harness.readTranscript` and resolves its URL and watch root through `Store.sessionIndex(for:)`. `TranscriptIndex` and `CodexIndex` implement `SessionIndex` (`root`, `url(ofSession:)`). Context is a computed read from the session summary so refreshed token counts and the rollout's context window reach the chip without Claude's activity report. Background tasks are not implemented for Codex.

`CodexTranscript` reads prompts and replies from `event_msg` user_message and agent_message records, including commentary and final replies. It also reads item_completed UserMessage and AgentMessage records. If the head contains item_completed, command execution and file changes use completed items; otherwise commands use response_item function calls and outputs, with patch_apply_end for changes. This era rule prevents duplicate tools. Adjacent duplicate prompts and repeated replies within a prompt are deduplicated. Web searches use web_search_end, and update_plan becomes a plan tool row. Polling and agent bookkeeping calls are omitted. Pull request tags come from standalone GitHub pull URL lines in gh command output.

`task_started` opens a turn; `task_complete` and `turn_aborted` close it. An incremental chunk's nil `isTurnOpen` leaves the previous state intact. A full read reporting an open turn whose newest entry predates the tab is treated as a dead turn. Open turns show Working. After 20 seconds without new entries or a turn-state change, a quiet hint offers Show Terminal. Codex does not use the missing-live-session terminal fallback.

Sending is refused while a turn is open and the draft is kept. Approvals are invisible in the rollout, so Enter could answer one instead of sending a message. Otherwise a tab must already be open, input waits until it is at least five seconds old, and the terminal receives bracketed paste followed by Enter after 300 ms. This sequence is unverified against a live Codex TUI. Stop sends Escape without requiring live status.

Attachments and model selection are off for Codex. Its context chip is read-only and opens the shared usage popover. The composer uses the harness name and keeps drops as a no-op when attachments are unavailable. Status and needs-you alerts remain Claude only.
