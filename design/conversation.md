# Conversation view

Moved from CLAUDE.md. The decision to read the transcript is docs/adr/0004. The Conversation view is the `.conversation` capability of a harness (docs/adr/0007).

Conversation view (Settings > General `conversationEnabled`, off by default; `conversationDefaultView` picks what new Claude tabs open in): a per-tab, in-memory mode (`Store.conversationTabIDs`, ⌥⌘J `AppAction.showConversation` / `.showTerminal`, View menu, palette, and a trailing toolbar button that switches to the other view) that shows the session as a conversation (`ConversationView`, `ConversationContent`, `ConversationModel`) in the terminal's card slot while the harness TUI keeps running in the hidden, still-mounted surface. It resolves the transcript and watch root through `SessionIndex`, reads through the harness transcript adapter, and runs `TranscriptActivity.report` for Claude. Codex reads its tasks through the harness and its context from refreshed session summaries. There is one reader per shown tab, dropped when hidden; the turn model (`Conversation.swift`) and `MarkdownBlock` live in BerthCore and compile into BerthRemote by path.

`SessionStatusBar` sits below the glass composer. The left side shows the folder, branch with ↑ahead ↓behind against the upstream (`ReviewGit.branchSummary`, polled every 20 s and after each turn), permission mode, and the context ring once the window is known. Permission mode comes from the latest `permission-mode` transcript line (`TranscriptActivity.permissionMode`). Clicking it sends ⇧⇥ through `Store.cycleMode` for harnesses with `.permissionModes` unless the session is waiting on a prompt. The right side shows the model and effort. Harnesses with `.modelEffortMenu` can change them while idle and open context details from the menu. Codex shows the context percentage when known and opens context details on click. The terminal draws its own statusline and the toolbar shows the context button when the conversation footer is unreachable.

The transcript scrolls behind a 28 pt fade into the opaque theme background under the composer and footer. The bottom inset keeps the latest message above the fade. The composer keeps its attachment and send controls inline with the text field until the draft contains a newline, exceeds the inline field width, or has an attachment. The same text field then spans the width above the controls and grows to eight lines.

Text arrives per content block, not per token. `Store.focusSelected()` focuses the conversation or the surface. The composer (`ConversationComposer`, an AppKit `ConversationComposerField` so pasted images can be caught: ↩ and ⌘↩ send, ⇧↩ and ⌥↩ newline; drafts per tab in `Store.conversationDrafts`) and the approval card (`ConversationApprovalCard`; `PendingApproval.resolve` in BerthCore maps permission prompts, single-select AskUserQuestion and plans to the keys the phone sends; ↩ allows with an empty draft, ⎋ denies, 1-9 answer) send through `Store.submit` / `press` / `interrupt` (`StoreInput.swift`), shared with `RemoteServer`.

`ConversationFallback` switches the tab to the terminal (`Store.conversationSuspended`) for an unrepresentable approval or question, or for missing approval details after 4 s. Harnesses with live session files also fall back after 10 s without a live session. Conversation resumes once the session is live and no longer waiting. A Code Mode script shows as its inner calls: they follow its REPL and Poll records as virtual records (`isVirtual`, tool_result id `repl_…`, empty content with the output in `toolUseResult`, read by `TranscriptTail`), and the wrapper is dropped. In turns Poll is dropped, REPL rows show their description, SendMessage reads Message(...) and `<system>` results read Done; finished work folds per run and replies are never folded. The "N running" capsule names its kinds ("1 agent · 1 shell", `RemoteTask.summary(of:)`) and opens the task list in a popover so the layout never moves (`-snapshotConversationTasks YES`; popovers are not captured offscreen). Spinners are `ConversationSpinner` (SwiftUI-drawn): an AppKit `ProgressView` rendered with the light appearance on its first frame.

Drops land on an AppKit `ConversationDropTarget` overlay over the card and composer. Run Berth snapshots under `env -i PATH=/usr/bin:/bin` from a Ghostty shell, or `ghostty_surface_new` crashes on the inherited environment.

Agent cards and running-agent popover rows open a conversation-pane overlay with Back/Escape navigation, reading turns incrementally from the subagent JSONL through the harness and watching its directory for live transcript and metadata updates.

Claude bash-mode commands appear as shell rows on Mac and Remote with stdout and stderr folded after four lines.

Codex rollouts supply turn-open state as well as entries. An open turn blocks sending and keeps the draft when the title supplies no usable status. The Action Required title gates approval and question cards, with details read separately from the rollout tail. A quiet Show Terminal hint appears after 20 seconds without new entries or a state change. Codex context is read-only, with no model picker or attachments. Sources, parsing rules and input limitations are in design/codex.md.
