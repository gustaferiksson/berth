# Conversation view

Moved from CLAUDE.md. The decision to read the transcript is docs/adr/0004. The Conversation view is the `.conversation` capability of a harness (docs/adr/0007).

Conversation view (Settings > General `conversationEnabled`, off by default; `conversationDefaultView` picks what new Claude tabs open in): a per-tab, in-memory mode (`Store.conversationTabIDs`, ⌥⌘J `AppAction.showConversation` / `.showTerminal`, View menu, palette, toolbar) that shows the session as a conversation (`ConversationView`, `ConversationContent`, `ConversationModel`) in the terminal's card slot while the harness TUI keeps running in the hidden, still-mounted surface. It resolves the transcript and watch root through `SessionIndex`, reads through the harness transcript adapter, and runs `TranscriptActivity.report` for harnesses supporting backgroundTasks. Other harnesses read context from refreshed session summaries. There is one reader per shown tab, dropped when hidden; the turn model (`Conversation.swift`) and `MarkdownBlock` live in BerthCore and compile into BerthRemote by path.

Text arrives per content block, not per token. `Store.focusSelected()` focuses the conversation or the surface. The composer (`ConversationComposer`, an AppKit `ConversationComposerField` so pasted images can be caught: ↩ and ⌘↩ send, ⇧↩ and ⌥↩ newline; drafts per tab in `Store.conversationDrafts`) and the approval card (`ConversationApprovalCard`; `PendingApproval.resolve` in BerthCore maps permission prompts, single-select AskUserQuestion and plans to the keys the phone sends; ↩ allows with an empty draft, ⎋ denies, 1-9 answer) send through `Store.submit` / `press` / `interrupt` (`StoreInput.swift`), shared with `RemoteServer`.

For harnesses with live session files, `ConversationFallback` switches the tab to the terminal (`Store.conversationSuspended`) for an unknown `waitingFor`, multi-question or multi-select questions, a permission prompt with no tool call after 4 s, or a session not live after 10 s, and back once it is live and not waiting. A Code Mode script shows as its inner calls: they follow its REPL and Poll records as virtual records (`isVirtual`, tool_result id `repl_…`, empty content with the output in `toolUseResult`, read by `TranscriptTail`), and the wrapper is dropped. In turns Poll is dropped, REPL rows show their description, SendMessage reads Message(...) and `<system>` results read Done; finished work folds per run and replies are never folded. The "N running" capsule names its kinds ("1 agent · 1 shell", `RemoteTask.summary(of:)`) and opens the task list in a popover so the layout never moves (`-snapshotConversationTasks YES`; popovers are not captured offscreen). Spinners are `ConversationSpinner` (SwiftUI-drawn): an AppKit `ProgressView` rendered with the light appearance on its first frame.

Drops land on an AppKit `ConversationDropTarget` overlay over the card and composer. Run Berth snapshots under `env -i PATH=/usr/bin:/bin` from a Ghostty shell, or `ghostty_surface_new` crashes on the inherited environment.

Agent cards and running-agent popover rows open a conversation-pane overlay with Back/Escape navigation, reading sidechain turns incrementally from the subagent JSONL and watching its directory for live transcript and metadata updates.

Codex rollouts supply turn-open state as well as entries. Open turns block sending and keep the draft because rollout files do not reveal approvals. A quiet Show Terminal hint appears after 20 seconds without new entries or a state change. Codex context is read-only, with no model picker or attachments. Sources, parsing rules and input limitations are in design/codex.md.
