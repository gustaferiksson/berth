# Review: implementation notes

Moved from CLAUDE.md. Flows and layout intent are in design/flows-review.md and design/review-panel.md; task cards are in design/flows-tasks.md.

## Panel, split and layout

Review (`design/flows-review.md`, opt-in via Settings > General `reviewEnabled`), strictly native: off means no menu item, palette row, toolbar toggle or ⇧⌘R routing (the key monitor skips ⇧⌘R while unavailable; Ghostty has no default ⇧⌘R). On, Show / Hide Changes (`AppAction.showChanges` / `.hideChanges`, ⇧⌘R) toggles `Store.showsReviewPanel`, a panel in whichever of the two native edge slots the session sidebar doesn't use (the `NavigationSplitView` sidebar column, or the `.inspector`); Harbor hides it, selection changes don't.

It follows the selected Claude tab (`Store.reviewModel`); terminal tabs get a `ContentUnavailableView`. The diff column sits beside the terminal area, on the panel's side, in `TerminalSplit` (an `NSSplitViewController` whose items are `NSHostingController`s, so the terminal item and its surfaces are created once); the diff item is expanded whenever the panel shows, so the terminal keeps its width as files open and close, and collapses only while the panel is hidden or Harbor is shown; with no tab it shows No File Open under an empty 32 pt tab strip row (nothing opens by itself).

`reviewTerminalBelow` (View ▸ Show Claude Below Diff / Show Claude Beside Diff, palette, no shortcut, default off) flips the split's `isVertical` in place (diff first, terminal below, items and surfaces never recreated; flip the orientation before reordering items, or the diff item ends up collapsed after a later resize). `fitDiff` then works on height: the diff gets `reviewTerminalBelowRatio` (default 0.6, written from `splitViewDidResizeSubviews` only while the current event is a mouse drag), each pane at least 160 pt, enforced in `constrainSplitPosition` (overriding `constrainMin/MaxCoordinate` on `NSSplitViewController` crashes in layout).

Its collapse is not animated. Both sides use `lineFragmentPadding` 0: TextKit 2 puts the container origin at -padding, and NSTextView's end-of-live-resize re-anchor (`scrollToLocation`, fired by divider moves and sidebar collapses too) then landed 5 pt right, clipping the first character (main does it on any window live resize). `ReviewTextView.viewDidEndLiveResize` restores the clip origin afterwards, since the re-anchor also drops the reader's horizontal scroll. No width minimums as constraints (`minimumThickness` included): once the window can't fit them, AppKit's update-constraints pass loops and throws (seen at the 1200 pt default); `TerminalSplitController.fitDiff` moves the divider instead, on expand and first layout (760 pt, less to leave the terminal 360, at least 440) and after each width change.

When the split settles under 801 pt with the panel shown (a `.task` 300 ms after the last width change; launch passes through transient widths of 0–454 pt) the session sidebar collapses (`sidebarYieldsToDiff`, an overlay on `columnVisibility` / `showsTrailingSidebar`, so nothing persisted changes; in below mode only the diff's 440 pt counts, so under 441 pt); hiding the panel restores it unless the user toggled it meanwhile. An explicit show of the session sidebar (`setSessions` with anything but `.detailOnly`) sets `keepsSidebarForDiff` and clears `sidebarYieldsToDiff`, so the 300 ms `yieldSidebarIfCramped` that follows the width change can't re-collapse it; hiding the panel resets both.

The terminal and diff are cards: their hosting views are layer-clipped to 12 pt continuous corners with a `CardBorder` (foreground at 10%), the split sits 8 pt inside the window chrome and `GapSplitView` makes the divider an invisible 8 pt gap; no hairlines or empty strips separate the columns. The column and inspector bindings echo programmatic changes into setters built for the other `sidebarPosition`, so `setLeadingColumn` / `setInspector` read live state and drop no-ops (a stale setter once wrote `showsTrailingSidebar = false` to the real defaults from a snapshot).

## Committed base and compares

Review's Committed base is chosen in this order (`ReviewChanges.baseReason`): the header menu's pick (`reviewBaseBranches`), the PR's `baseRefName`, the configured base (`gh-merge-base` or an upstream on another branch) when it isn't the default branch, the first candidate (the nearest `origin/` one, a local branch only when none), then the default branch. Candidates (`ReviewChanges.bases`) are local and `origin/` branches between the merge base with the default branch and HEAD (`for-each-ref --merged=HEAD --contains=<merge base>`), minus the own branch, its `origin/` twin and refs at HEAD or the merge base; a remote twin at the same commit wins, `origin/` refs before local branches, each nearest first, default branch last.

The header's "→ base" is a plain-style `Menu` with an inline `Picker` ('ref · N commits', '· PR base'); Create Pull Request… adds 'against <base> with gh (--base <base>)' when the base isn't the default branch. Only the configured base is fetched. Two compares from `ReviewGit.changes` (the panel's only diff call): Uncommitted (HEAD to the working tree) and Committed (merge base to HEAD, none on the default branch or without a base).

## Changes, Files and Graph

The panel is the Changes list over the Files or Graph pane (`Sources/ReviewFilesSplit.swift`). Each scrolls independently. Drag the divider to set `reviewFilesRatio` (default 0.45) or double-click it to reset. The title buttons persist the selection in `reviewBottomPane` and expand the pane. The chevron toggles expansion. Reveal in Files opens Files, and a stored `reviewPanelTab` of `files` or `graph` opens that pane.

`ReviewModel.loadGraph` in `Sources/ReviewView.swift` starts with 200 commits when Graph first appears and appends 200 at a time. Refresh reloads at least the loaded prefix after Graph has been used. `ReviewGit.graph` walks branch, remote and tag tips plus HEAD in topological order. `ReviewGraph.layout` assigns lanes to pending parents as it walks that order, reusing free lanes and keeping the existing prefix stable as pages are appended. `Sources/ReviewGraphView.swift` draws up to eight lanes.

The panel used to start with an icon-only segmented `Picker` (`ReviewPanelTab`: `changes`, `files`; `reviewPanelTab`, default `changes`, persisted only while `persistsTabs` is on) and the Refresh capsule on both tabs (32 pt row, hairline below); the `branch → base` menu and tree button sit at the top of the Changes tab; every tab top-aligns, so an empty state sits under the bar. A stored `comments` or `preview` is moved once (while `persistsTabs` is on, or per launch in snapshots): `preview` opens the diff column's Preview, `comments` expands the comment list, and the stored value becomes `changes`: Changes (the branch or task card, then Uncommitted and Committed in one `List`, each a `Section(isExpanded:)` with the sidebar's `GroupHeader`, collapsed ids in `collapsedReviewSections`, comma-separated `uncommitted`, `committed`, default empty), Files (the Files outline in its own scrolling `List`, flat indented rows with their own chevron buttons over `ReviewFileTree`, expanded folders in `ReviewModel.expandedFolders`, in memory, keyed by path) and, pinned at the bottom of the panel on every tab (a sibling below the list in the panel's VStack, hidden at 0 comments), the comments bar: a "Comments N" disclosure (`ReviewModel.showsCommentList`, in memory, scrolls past 220 pt; a row opens its document on a click, `×` deletes) and a `.glassProminent` Send N Comments button.

File rows end with a small M/A/D letter in a fixed 12 pt column after the +/- counts. Review section headers are ordinary rows (not `Section` headers, which sat 2 pt off the rows; `GroupHeader` takes the review inset through the `headerInset` environment value) whose `GroupHeader(isExpanded:)` is one `Button` with its own chevron (the system `Section(isExpanded:)` header ignored clicks on screen); the PR section is titled by the branch when no PR shows, and other PRs list as a state dot, "#n title" on 2 lines and a "State · checks" caption.

Reveal in Files (`ReviewModel.filesReveal`) switches to Files, which expands the parents and scrolls on mount. File rows are tagged `ReviewDocument`, a Files row with the plain file, which the selection setter and double-click map through `workingDocument`; folders are untagged (a tagged folder opened as a file on double-click), and a folder's label is a plain `Button` that toggles it (a double-click toggles once and opens nothing); it takes `.listRowInsets(.vertical, 0)` and pads itself by 5 pt instead, since clicks in a row's insets never reach the label.

`.selectionDisabled()` sits on the label (on the `DisclosureGroup` it also disabled the folder's files). Row titles pin `.fontWeight(.regular)`: a file row created while already selected (parents expanded by the reveal) drew its title bold and kept it. Uncommitted and Committed rows end with an Open File button in a fixed-width column after the counts (the Uncommitted header's totals line up with the counts; Committed's header sums its rows the same way), shown only while the row is hovered or its path is the open tab, which opens the plain file; deleted files have none, and Files rows open the plain file on click.

The branch card's stats line shows `ReviewChanges.total`: the working tree against the merge base (untracked files included, binary files as 0), computed per path in `ReviewGit.changes`, nil on the default branch or without a base; after the commit count without a PR; with one, `+x −y` sits right-aligned on the checks row. The PR card's first line is a square state tag (a click opens the PR) and `#n`, then the title, `branch → base`, the checks row and the commits disclosure; its only button is the ⋯ menu.

PR tags (`PullRequestTag`, the card's state tag) are square 4 pt, issue pills (`IssueTag`, `IssueStatePill`) are capsules. The panel header's View as Tree / View as List button (left of Refresh, `reviewChangesAsTree`, off by default) shows Uncommitted and Committed as folder trees: `ReviewFileTree.compactNodes` (Files' `nodes`, then single-child folder chains merged into one row joined with "/", keyed by the deepest folder's path) rendered by the same `ReviewFileNode` as Files with the section's compare, so folders are the Files folder button and file rows are the list's `ReviewChangeRow`, padded like folder rows (25 pt, list rows stay 24).

Folders start expanded; collapsing is in memory in `ReviewModel.collapsedChangeFolders` (folder path plus compare), and a change of the selected document reopens its collapsed parents in its own section. The Changes list's `.id` is its tree-mode folder paths per section (`ReviewFileTree.folderPaths`, nil in list mode): when a reload compacted or uncompacted a folder, or the list switched to tree, SwiftUI's outline list kept stale rows (a ghost row drawn over another) and the next update threw "no common ancestor" (ListHeader/ListRow) from `reloadItem` in `configureCell`, killing the app; those changes now rebuild the list (scroll resets) instead of diffing it.

The session's comments and Send N Comments sit below.

## Documents, tabs and history

A document is a path plus a compare (`ReviewDocument`; `compare` nil is the plain file). The diff column has VS Code preview tabs (`ReviewModel.tabs`: a history of (document, range) entries and an index each, at most one preview tab; `open` selects a tab already showing the document, else navigates the preview tab and drops its forward history, else inserts one after the current tab; `keep` on double-click or edit). Below the strip a 22 pt path bar (`ReviewPathBar`, its own hairline) shows `repo › folders › file` for the current tab (the repo segment is the main checkout's name; folders collapse to … when narrow), each segment a borderless `Menu` of that folder's children from `ReviewModel.tree` (files open through `ReviewModel.open(workingDocument)`), with the compare as plain text on the trailing edge.

One 32 pt strip holds Back/Forward at the leading edge and the layout toggle and Save (icon) at the trailing edge, with no header row or compare chip; tabs whose file names collide show their shortest distinguishing parent folders dimmed, the tooltip is the path plus (Committed)/(Uncommitted), and the context menu has Copy Path, Copy Relative Path, Reveal in Files, Close and Close Others. The tab list scrolls horizontally and keeps the selected tab in view. Preview is a tab pinned after it (`ReviewModel.isPreviewOpen` / `isPreviewSelected`, in memory): dimmed with a globe while closed, opened by a click, View ▸ Open Preview or the palette (`AppAction.openPreview`, no shortcut), with a × while open.

Assigning `selectedTabID` deselects it, ⌘W / `Store.closeDiff()` closes only Preview while it is selected, and its `WKWebView` lives in `ReviewModel.preview`, so switching tabs keeps the page. `-snapshotPreview <address>` opens it first. ⌘-click definitions and opening a reference from the peek first store the position they leave (the clicked offset on the right side, else the right side's selection) on the current entry, then push the target with its range and drop forward history: a same-file target is pushed on the current tab (unless it starts at the clicked position), another file goes through `open` and its entry gets the range.

Back / Forward (`ReviewModel.go(by:)`, the header's chevrons, ⌃- / ⌃⇧-) restore the entry's document, select and scroll to its range through `reveal` (a zero-length range selects the identifier there) and refocus the editor (`focusesEditor`). History is per tab, so a cross-file ⌘-click from a kept tab lands in the preview tab with no way back to the origin. List selections are derived from the current tab, double-click is `contextMenu(forSelectionType:primaryAction:)`. Refresh maps each history entry to its compare if still listed, else the plain file while it exists, else drops it (ranges are kept; `offset(of:)` clamps them to the text), and closes a tab whose current entry dropped.

Uncommitted compares and plain files are the working tree and share the path's editor, history, draft, `loadedTexts` and language-server sync (a load or save updates every loaded working-tree document of the path, so a tab switch never resets undo). A Committed compare whose path is also Uncommitted gets a fresh read-only `ReviewTextView`, a constant nil draft, no diagnostics and no sync: its language questions go to the working text (`ReviewModel.workingText`); otherwise HEAD is the working tree, so it shares the path's editor, draft and save (the pane's identity includes read-only, so the shared editor is never re-hosted read-only).

A save there marks the path (`savedFromCommitted`); once a reload lists it as Uncommitted, tabs on its Committed compare switch that entry to the Uncommitted compare (same editor, so selection and undo stay; focus returns if the editor had it; scroll resets to the top). A plain file, and a compare of an added or deleted file (`ReviewModel.selectedDocumentHasBothSides` false, from the listed status), is forced unified, so it's a single pane; a plain file diffs its draft against itself (`ReviewDiffAnalysis` `base`), so unsaved edits show no diff.

`ReviewCompare.commit(sha)` uses the file list and blobs from `ReviewGit.commitFiles` and `ReviewGit.contents`. The comparison uses the first parent (the empty tree for a root). `ReviewModel` preserves these documents on refresh, and `ReviewDiffPane` displays them read-only with no working-tree draft, language-server sync or gutter comments.

`dismantleNSView` removes only its own coordinator's inline views and resets the editor only while it is still that coordinator's delegate, since two panes can re-host one editor. Comments carry their compare (`ReviewComment.compare`); cards filter on path and compare, and the prompt marks Committed blocks `(as committed)`. When the current tab's path changes (and when the list appears), or Reveal in Files sets `ReviewModel.filesReveal` (which also expands a collapsed Files section), the Files list adds its parent folders to the expanded set and scrolls to its row (`ScrollViewReader`), and the revealed row highlights.

## Model, reload and git errors

State is a `ReviewModel` per session in `Store.reviewModels` (created by `prepareReviewModel` while the panel is shown, replaced when the tab's folder (`tab.cwd`, set by each scan) differs from `ReviewModel.folder` unless it has drafts or comments (then `movedFolder` shows a notice until both are gone; it clears if the session moves back), dropped when the tab closes or the setting turns off), so drafts and comments survive switching sessions; unsaved drafts keep `Store.isIdle` false. While the panel shows a model (not hidden, not under Harbor, Review on; showing it again reloads), `Store.watchReview` keeps one `FileWatcher` on the repository root and the common git dir, keyed in `ContentView` on the shown model's root.

In the git dirs only the own git dir's `HEAD` and `index`, `packed-refs` and `refs/` (not `.lock`) count, so other worktrees' entries don't; working-tree paths under `ReviewGit.ignoredDirectories` (gitignored directories, re-read before each reload) don't. Review's own saves reload too (the atomic write's temp path defeated a filter), which updates the counts. The reload runs 500 ms after the last event through `Store.refreshReview` (scan, `prepareReviewModel`, the shown model's `load()`), which Refresh also uses, so a moved session is followed at once.

`load()` is serialized, and requests made while one runs share one follow-up load. A failed load keeps the last lists and shows a warning by Refresh, and `load()` keeps the selected tab's contents until they're reloaded. With nothing loaded, the panel shows a `ContentUnavailableView` per `ReviewGitError` from `ReviewGit.changes`: `notARepository` (rev-parse failed and `RepositoryRoot.enclosingRepository` finds no `.git` above the folder) is a calm No Git Repository without a button; `folderNotFound`, `gitNotFound` (a `git --version` probe fails too, e.g. the xcrun shim without Command Line Tools) and any other git error show Folder Not Found, Git Not Found or Can't Read Changes with the raw message and Try Again.

While the shown model is `notARepository`, `Store.watchForRepository` watches its folder and reloads once the folder's own `.git` appears (both sides go through `resolvingSymlinksInPath`, which strips `/private`). A repository without commits compares against the empty tree (`hash-object -t tree /dev/null`) and takes its branch name from `symbolic-ref`. The model also keeps each file's right-side `ReviewTextView` (`ReviewModel.editors`, created when its contents load) and its `history` undo manager: NSTextView's undo actions edit the view that registered them, so a new pane (file switch, Refresh) re-hosts that view, and only incoming text that differs from it (a reload from disk) replaces its text and clears the history.

## Saving, sending and pull requests

Save (File ▸ Save, ⌘S, the tab strip's Save: `AppAction.save`, routed past the terminal by the key monitor) is available while the selected document's path has a draft and writes that path's editor text at that moment through `ReviewGit.save`, refused when the file changed on disk since it was loaded. Esc in a `ReviewTextView` only dismisses the hover card (`cancelOperation`; NSTextView's default runs word completion). Send pastes `ReviewComment.prompt` into the session's tab without Return, only while Claude is live there.

The branch card's Create Pull Request… (only for a known no-PR, `(repository, nil)`, on a non-default branch with a base and at least 1 commit ahead) pastes "Push this branch and open a pull request for it with gh." the same way and focuses the terminal; it is disabled with a tooltip while Claude isn't live in the tab. The new PR appears with the sidebar's next lookup (activation or the 5 min poll, at most once a minute), or at once on the panel's Refresh, which looks up the panel's branch in its repository through `Store.fetchPullRequests` (unthrottled) whenever the card knows its PR state.

Below the panel header sits a PR or branch card (`design/flows-review.md`): `ReviewModel.changes` + `status` (`branchStatus`, loaded with the lists; the default-branch title says "No uncommitted changes on <branch>" with a clean tree) and `pullRequestDetails` (per PR number, `PullRequestStatus.detail`: one `gh api graphql` for the panel's PR only, never in the sidebar's batch). `Store.pullRequest(in:branch:)` returns nil while unknown and `(repository, nil)` for a known no-PR, which alone shows the "No pull request" pill.

## Closing tabs and find

While the panel is shown, ⌘W from any focus in the main window (terminal included) closes the current diff tab and otherwise does nothing; it never closes a session or the window (Ghostty's `super+w` would run `close_surface` and close the tab, File ▸ Close would close the window and quit). With the panel hidden, it closes the current tab only while one is open and no terminal surface is focused (`Store.closeDiff(tab:)`, also each tab's ×; closing the last one leaves No File Open and focuses the terminal).

Closing the current tab while others remain focuses the next tab's right side (`ReviewModel.focusesEditor` → the pane's `takesFocus` → `ReviewTextView.focusesInWindow`, applied once the view is in the window: a focus call on the next run-loop pass missed 1 in 5 runs); ⌘F anywhere in the diff column opens the focused side's find bar (the key monitor takes both). With a single-line selection, ⌘F first runs `NSTextFinder`'s `setSearchString` (like ⌘E), so the find field starts with the selection; an empty or multi-line selection keeps the last search.

## Diff text views and layout

The diff is two `ReviewTextView`s (TextKit 2) over one aligned row model (`ReviewDiff.Side.rows`, each line's row; rows a side has no line for are filler). Filler rows and `reserved` comment space (points after an aligned row, identical on both sides) are paragraph spacing added by the content storage delegate to display-only paragraphs (space before line 1 is `minimumLineHeight`, TextKit ignores `paragraphSpacingBefore` on the first paragraph), so every row's y is arithmetic (`top(ofRow:)`) and inline views, minimap and ruler never query layout.

Side by side, each side is a gutter plus scroll view stack inside an `NSSplitView` (`ReviewSplitView`, thin divider, then minimap and ruler in the outer stack); the coordinator, as its delegate, lays the sides out from `reviewSplitRatio` (left width over the split's width less the divider, default 0.5), at least 200 pt a side (half each when both can't fit), enforced in the constrain methods, never as constraints. Only a divider drag writes the ratio (`mouseDown` returning with the divider moved): `splitViewDidResizeSubviews` carries `NSSplitViewDividerIndex` on programmatic resizes too and wrote 0.5008 at launch.

A double-click on the divider writes `ReviewSplitView.resetRatio` (0.5 here). Comment cards take their owner side's clip width. Gutters, minimap and ruler set `clipsToBounds` (off by default since macOS 14): the gutter drew a half-hidden top row's number over the diff header. Changing `reserved` re-sets attributes only on the paragraphs carrying the changed rows (a full refresh cost 224 ms on 5,000 lines in Debug, this 40 ms). It then runs `layoutSubtreeIfNeeded()` and redraws the side and its gutter: TextKit 2 draws each line through an `_NSTextViewportElementView` that only NSTextView's layout pass moves, so until it runs, lines under a new card stay at their old y and show through it (seen once in the app, never reproduced; `layoutViewport()` alone left the views stale).

An empty side (added or deleted file) has no paragraphs, so the delegate can't pad it: `minimumHeight` gives it its partner's height (`minSize` is reset by the scroll view), or it can't scroll. Added and deleted files are always unified: a deleted file's right view holds no text and only paints the removed rows in `drawBackground`, on the plain background (the absent side's filler fill is side by side only), so its lines can't be selected or found.

## Syntax colours

Syntax and changed words are rendering attributes set in `renderingAttributesValidator`, so the text storage only ever holds font, colour and paragraph style; the validator colours each paragraph once per `refresh` (`coloredParagraphs`, tested with `contains`: `IndexSet.insert` always reports `inserted`). Captures map to colours in `ReviewStyle.color(forCapture:)`, shared by every language: `variable` and `variable.parameter` take the scheme's `variable` slot (One Dark #E06C75, GitHub foreground), the exact `constant` and `variable.builtin` its `constant` slot, `string.regexp` its `regexp` slot (values from the One Dark Pro and GitHub VS Code themes).

`punctuation.bracket.0` to `.2` (`()[]{}` by nesting depth, set in `ReviewHighlighter.spans`; `<>` and mismatched closers stay plain) take the scheme's three `brackets` slots (One Dark #D19A66, #C678DD, #56B6C2); `variable.local` has no slot and draws as the foreground. TypeScript and TSX also load Berth's `Resources/highlights-typescript.scm` (`Grammar.init`'s `berthQueries`, a `project.yml` resource; JavaScript doesn't) after the package queries: top-level `const` names (yellow; local ones `variable.local`), shorthand properties (variable slot), `=>` (keyword slot), function-valued declarators, capitalised members and whole regexes.

Indent guides (`ReviewTextView.drawIndentGuides`, `ReviewStyle.indentGuide`) are 1 pt lines drawn after the row fills over visible rows only, one per `indentUnit` (2 or 4, picked per file; a tab is 4 columns), blank lines taking the lesser neighbouring indent, none on unified removed rows. Fira Code's ligatures render with the default attributes, so no feature is set. SwiftTreeSitter sorts spans by node depth first and the last covering span wins, so a deeper node's capture beats an ancestor's (the regex's closing `/` needs its own pattern); a missing or broken query turns highlighting off for that language silently.

## TextKit 2 layout (see docs/adr/0003)

Both sides lay out fully (`ensureLayout`, ~70 ms per 5,000 lines) and then take that layout's height, so their heights match and scroll sync is the clip view's y. The layout must stay whole: TextKit 2's `layoutViewport` flushes fragments outside the viewport, which come back at estimated positions off `top(ofRow:)`, and NSTextView's `textContainerOrigin` getter (also through `super`) then lays out the whole document again (the old 0.45 s per side scroll stall on a 29k-line file). `makeSide` therefore switches each text view's layout manager to `ReviewTextLayoutManager` (`object_setClass`), whose no-op override of the private `flushTextLayoutFragmentsFromLocation:direction:` keeps every fragment; if a macOS release renames that selector the stalls return (a `-snapshotReview` wheel scroll through package-lock shows it).

Overriding the getter or pinning the frame instead left jumps and the document end at estimated positions (see docs/adr/0003-textkit2-flush-override.md). `ReviewTextView.layoutManager` returns nil: reading it on an NSTextView silently switches to TextKit 1. The gutter is a sibling view, not an `NSRulerView` (on macOS 26 the ruler overlays the clip view instead of tiling beside it), and fills `bounds`, not `dirtyRect` (views don't clip to bounds, so a dirty rect fill painted over the whole screen). Gutter, minimap and ruler forward `scrollWheel` to the scroll view.

The gutter draws no separator of its own: the diff column is a bordered card, and a unified-mode gutter line once doubled its boundary line.

## Inline comments, minimap and style

The panel and diff read the shown PR's cached `PullRequestDetail.threads`. `ReviewThreadCard` shares the local comment spacing in `ReviewDiffPane`, with original-side anchors mapped through the removal rows in unified mode. The panel opens the committed compare when available and queues a side and line for the pane to scroll to after applying its analysis. Reply drafts stay in `ReviewModel` until sent or cancelled. Replies and local line comments use the model's pending review writes, then reload the PR detail. Sending a thread to the session uses the same prompt paste path as local comments.

Comments are inline: `ReviewInlineComment` views are subviews of the owning text view (they scroll with it), the draft box below the selected lines and a card per comment (`ReviewComment.side`, removals on the left, or under the removed row on the right when unified), built from `model.comments` so the file column and the card's × stay in sync. One click on a card's text (`ReviewCommentField.onClick`, since the card body is the field; it accepts the first mouse, so it works in an inactive window) opens the draft box in the card's slot, prefilled with Save. A card shows a subtle fill and the × on hover, and its context menu offers Edit Comment, Copy Comment and Add to Pull Request Review. `draft.editing` holds the comment id, the card hides while it is open, and ↩ writes `ReviewComment.text` in place (an empty ↩ keeps the old text, Esc cancels).

Opening an edit or a new selection replaces whatever box is open, discarding its text. Double-clicking a comment in the panel opens its document and sets `ReviewModel.editingComment`, consumed once its analysis is applied. The comment field's container doesn't track its view width (`widthTracksTextView` off): with it on, a new card's first measurement came out one line short. The box's `ReviewCommentField` handles ↩ (add), ⇧↩ (newline) and Esc in `keyDown` (not `doCommandBy`, so it doesn't depend on `NSApp.currentEvent`), skipping marked text.

The minimap (`reviewShowsMinimap`) renders one CGImage per analysis, style or `reserved` change and only blits it plus the viewport on scroll; taller than the view it scrolls proportionally like VS Code's. Every colour and font in Review comes from `ReviewStyle` (Settings > Appearance > Review: scheme, font, size, line height; Match Terminal, the default, derives from `GhosttyTheme`, so the diff follows the app appearance), built in `ReviewDiffColumn` from its `@AppStorage` keys and passed down; a change restyles at once, open comment box included.

The panel uses the Ghostty theme like the sidebar; the diff column sits on the style's background with its `colorScheme` (the title bar keeps the window chrome), and the diff's stack gets the matching `NSAppearance`. Rows are `style.lineHeight` tall with the glyphs centred by splitting the extra into line height and paragraph spacing (`rowPadding`): `.baselineOffset` made TextKit 2 lines fractional and broke alignment.

## Unified mode

The diff is unified when `reviewDiffLayout` is `inline`, or `auto` (default) below 760 pt of diff column (`ReviewDiffColumn`'s `onGeometryChange`, applied 50 ms after the width settles and only while the panel shows); the tab strip toggle, View ▸ Show Side by Side / Show Inline and the palette (`AppAction.showSideBySide` / `.showInline`, while a compare with both sides is shown; `Store.isReviewDiffUnified` mirrors the column's mode) set an explicit value, and nothing sets `auto` back. Unified: both views take `ReviewDiff.unifiedOriginal` / `unifiedModified` (each hunk's removed rows before its added rows).

The left view stays the base's holder, its pane removed from the split view; the right view's `unifiedOriginal` points at it and its `drawBackground` paints each removed line in its padded gap (removed tint, base syntax runs and changed words, drawn as a string with the view's paragraph style), so the text storage stays exactly the file (editing, undo, save, LSP offsets) and removed lines can't be selected or found. The gutter numbers them with base numbers. That pass is skipped while the right side's rows are stale (`side.lineCount != lineStarts.count`).

`minimumWidth` widens the right side to the left's usage width, since a removed line can be the longest. A gutter drag starting on a removed row selects base lines (a removal comment), anything else file lines; every box and card then lives in the right view, drafts are stored as (side, line) and cards re-parent, so both follow a mode switch, and the top visible line is kept across it. Italic comments are the one font change in the text storage (rendering attributes ignore `.font`).

## Language servers

Language servers (Settings > General `languageServersEnabled`, shown while Review is on, off by default since servers and build scripts run repo code) are user entries (`LanguageServerEntry`: command, arguments, languages as extensions or language ids, root markers, optional settings JSON, diagnostics only or also definition and hover, enabled), edited in Settings > General > Language Servers and stored only in UserDefaults (`languageServers`), never read from a repo. SourceKit-LSP, rust-analyzer and typescript-language-server are default entries; `LanguageServerEntry.configured` puts stored entries first and appends defaults whose id isn't stored, so an edited or disabled default sticks.

`ReviewLanguage` (a `ReviewModel.language` per repository root) owns one `LanguageServer` per entry and server root, started by `sync` (the one spawn gate, which reads the setting) when a file's text is shown, a draft settles after the 300 ms recompute or the entries change, stopped when the model drops (`Store.reviewModels` `didSet`), the setting turns off or `sync` finds its entry edited or disabled. The server root is the nearest folder from the file up to the repo root holding a root marker (none found: no server; no markers: the repo root); Swift's marker is `Package.swift` (sourcekit-lsp rooted at a parent answers "No language service").

Commands resolve from `<server root>/node_modules/.bin`, then PATH, then known install folders, then `/opt/homebrew/bin` and `/usr/local/bin`; a node-shebang script runs through a resolved `node` (an app opened from Finder has none on PATH). An entry's settings answer `workspace/configuration` by dotted section and go out once as `didChangeConfiguration`; `workspace.configuration` is declared only when there are settings. Servers that advertise `diagnosticProvider` are also pulled (`textDocument/diagnostic`) after each open and change: vscode-eslint only pulls, and without settings (at least `{"validate": "on", "nodePath": null, "experimental": {}, "problems": {}, "rulesCustomizations": []}`) it lints nothing.

Diagnostics are kept per server and merged per file, each labelled by `source`, else the entry name. Hover and definition ask the file's non-diagnostics-only servers in entry order and take the first answer. Only the working tree syncs; its string is the file text, so UTF-16 offsets are LSP characters. Hover, ⌘-click and Find References work on both sides of every compare and on unified removed rows. A position in other text (base, HEAD) maps to the working tree when `ReviewDiff(original: that text, modified: working)` leaves its line unchanged.

Otherwise the question goes to that text opened as a hidden sibling `.berth-<8 hex>-<name>` in the file's folder: never written, opened and closed per request, its diagnostics dropped (a custom scheme or `untitled:` URI resolved nothing across files in sourcekit-lsp or typescript-language-server; a sibling `file:` URI resolves in both). Sibling answers map back to the working tree when their line is unchanged, else select in the clicked side (unified, whose left pane is out of the window: scroll to the row).

On a unified removed row the right view's pointer target comes from the hidden left view's line fragment x (`identifier(onLine:atX:)`) and `top(ofRow:)`. Deleted files get none. Questions send the current text first, use only a running or starting server, and retry once after 500 ms on -32801 or an empty answer within 10 s of start. A finished diagnostics stream (crash) forgets the server; the next sync starts a new one. Diagnostics are kept per resolved file path and drawn in `drawBackground` from `enumerateTextSegments` (not rendering attributes: `colorSyntax` resets those per fragment), zero-length ranges widened to the token, positions clamped to `lineStarts`; the gutter gets a severity dot and is the only tooltip owner (the text shows diagnostics in the hover card).

Tags (`tagSupport` on `publishDiagnostics`, `LanguageServerDiagnostic.tags`) follow VS Code: Deprecated is a 1 pt strike in `style.foreground` drawn under the glyphs in `drawBackground`, Unnecessary fades the text to 0.6 alpha in `colorSyntax` (`taggedRanges`; `placeDiagnostics` recolours only paragraphs whose tags changed), and a hint or info diagnostic with tags gets neither squiggle nor gutter dot. Glyphs draw in an `_NSTextContentView` subview, so nothing the text view paints covers them, `invalidateRenderingAttributes` without a layout pass strips the syntax colours, and `.strikethroughStyle` is ignored as a rendering attribute.

Selection occurrences follow VS Code: a single-line, non-whitespace selection (one range) is searched 100 ms after the last selection change, case-sensitive and literal, whole-word when the selection is exactly an identifier (`identifierRange`), off the main thread on a copy of the string, capped at 2,000 and shown only with at least 2 matches. `ReviewTextView.occurrences` is cleared by an edit (`didChangeText`) or an empty selection, and boxed (foreground at 12%) in `drawBackground` over the visible lines only, skipping the selection itself.

The ruler (2 pt marks, foreground at 55%, under the change lanes) and the minimap (row bands, foreground at 30%) mark `occurrenceRows` with one `cgContext.fill(rects)` each, through `top(ofRow:)`, skipping a hidden left side. Removed lines drawn in the unified gap aren't searched.

## Hover, definitions and references

Hover is a layer-backed card subview after 500 ms on an identifier or a diagnostic's range. Each part is a read-only selectable TextKit 1 `NSTextView` (`HoverCardText`, `AXStaticText` inside an `AXGroup` card), so the text is copyable (⌘C and the context menu act on the card's own selection, which never touches the editor's) and the I-beam shows. The card closes on Esc, scroll, edit, a click anywhere outside it (a local mouse-down monitor) or the pointer leaving the editor; leaving the hovered range for empty text starts a 300 ms grace that entering the card or returning to the range cancels, and the card stays while the pointer is over it.

Content: the diagnostics under the pointer (message in the severity colour, `(source)` secondary), a hairline, then the server's hover; either part alone when the other is empty; ⌘ held draws a link underline in `style.link` with the pointing hand, and ⌘-click goes to the definition (recorded in the tab's history, see above): the same file scrolls and selects, another file in the repo opens in the preview tab (its Uncommitted compare when listed, else the plain file; never a read-only Committed compare) and `ReviewModel.reveal` selects it once its analysis is applied; files outside the repo do nothing.

When the definition is the clicked position itself, ⌘-click opens Find References instead (VS Code), as do the text view's context menu and ⇧F12 (`ReviewTextView.keyDown`, not an `AppAction`: a menu shortcut would take ⇧F12 from terminals, and the palette has no caret). `textDocument/references` includes the declaration; sourcekit-lsp answers zero-length ranges, widened to the identifier. `ReviewReferencesPeek` is an inline view like the comment boxes (a subview of the owning text view, its owner side's clip width, reserving `ReviewReferencesPeek.height` (260) side by side or `stackedHeight` (360) stacked under the clicked row on both sides, picked in `layoutInline` from that width): a read-only preview and an `NSOutlineView` of references grouped by file, the current file first, old-text answers as `<path> (old)`.

Click or ↑↓ previews, double-click or ↩ opens like ⌘-click, Esc (list or preview) or × closes, and editing or reloading either side closes it. The preview and list sit in a `ReviewSplitView` (thin divider), with the peek as its delegate: side by side from `ReviewReferencesPeek.stackedBelowWidth` (560 pt of peek width), below that stacked with the preview on top (the peek's `layout()` flips `isVertical`, so it follows live resizes; it follows the diff column, so a side-by-side diff's peek nearly always stacks); the list's share of the width (stacked: the height) less the divider is `reviewReferencesSplitRatio` (default 0.38, one value for both), at least 100 pt a side, 60 pt stacked (half each, rounded down, when both can't fit, so a pinned divider never writes), enforced in the constrain methods; only a real divider drag writes the ratio and a double-click resets it (`resetRatio` 0.62, the preview's share).

The divider's effective rect is its drawn rect widened 3 pt across it (dx side by side, dy stacked), and the peek's four arrow cursor rects leave that rect out (refreshed after each divider move) so the split's resize cursor shows. The preview restores its clip origin in `viewDidEndLiveResize` (NSTextView's end-of-live-resize re-anchor, fired by every divider move, scrolled it 13 pt right). Rows use a row view whose `isEmphasized` is always false, so the selection is grey like every other list in Berth (`ReviewStyle.selection` is blue in both GitHub schemes and under Match Terminal).

Writing Tools are off (`writingToolsBehavior = .none`) on both diff sides, the comment field and the preview. `didClose` is only sent for the hidden siblings: editors live as long as the model, whose stop ends the server. TypeScript 7 ships no `tsserver`, so typescript-language-server needs TypeScript 5. Biome's `lsp-proxy` daemon exits when Berth disconnects.

## Multi-cursor

Multi-cursor (`ReviewTextView+Carets.swift`, ported from monotext, editable side only): the view keeps `carets` (ranges, primary, history) and mirrors only the primary into NSTextView's selection; typing, delete/insert/transpose commands, paste (one clipboard line per caret when the counts match), cut and IME commits fan out by setting each caret as the selection (last first) and calling super, inside one undo group that also restores the carets, so the text storage stays the file and the draft, recompute, save and language-server paths run per edit.

Moves fan out the same way; `…AndModifySelection:` runs the plain move from each caret's head, since setting the selection drops NSTextView's anchor. ⌥-click adds or removes a caret (ignored off a text row: removed lines, fillers, comment space), ⇧⌥-drag column-selects, Esc collapses (`doCommand` catches `cancelOperation:`). Edit ▸ Selection is `AppAction.caret(CaretAction)` (Add Cursor Above/Below ⌥⌘↑↓, Add Next Occurrence ⌘D, Move Last Selection to Next Occurrence, Select All Occurrences ⇧⌘L, Change All Occurrences ⌘F2, Add Cursors to Line Ends ⇧⌥I, Undo Last Cursor Operation ⌘U, Collapse to One Cursor with no shortcut, because a menu Esc would take it from the terminal), routed by the key monitor and enabled only while `Store.isReviewTextFocused` (set in `becomeFirstResponder`, cleared in `resignFirstResponder` and in `viewWillMove(toWindow: nil)`, because a closed diff leaves the window without resigning); not in the palette, which takes focus.

Add Cursor Above/Below steps through `lineStarts`, not y, so it skips fillers and removed rows. Occurrences search from the primary selection and skip every caret's selection. Extra carets and selections are drawn last in `drawBackground` from `segments(of:)` (a zero-length range gives a zero-width rect), carets in `style.foreground` with a 0.5 s blink timer restarted on every caret change.
